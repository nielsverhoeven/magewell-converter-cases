# cad/: tool-neutral design data, solver and tests

Text and Python that describe the cases without any CAD tool (issue #75, Fusion migration). Layers, top down
(a lower layer never imports a higher one; `cad/tests/test_layers.py` enforces it):

| Layer | Files | Role |
|---|---|---|
| P2 | `rules.py` (issue #78) | design rules under their Tier-1 ids |
| P1 | `layout.py` (issue #77) | case solver: numbers, counts and suppress flags; writes `parameters/variants/*.json` |
| P0 | `params.py`, `numeric.py`; data: `parameters/constants.csv`, `data/*.json`, `devices/*.json`, `cases/*.json` | the only reader of the data formats; OpenSCAD numeric semantics |

## Data

- `parameters/constants.csv`: the registry, one row per constant. Columns `name,unit,expression,comment`; unit is
  `mm`, `deg` or `none`; the comment is `description | src=<path:line or record id> | conf=<level>` (an expression
  row has no `conf`). Expressions use the neutral grammar of `params.py` (`+ - * /`, parentheses, `min`, `max`,
  `sin`, `cos`, `tan`, numbers with `mm` or `deg`); `params.emit_fusion()` is the only place that writes Fusion syntax.
- `data/*.json`: selection tables and per-kind maps. `devices/<slug>.json`: device facts with a confidence per port.
  `cases/<slug>.json`: options only (`fan`, `splitter`, `fan_switch`, `lid_vents`, `rail`, `fan_y`). `configurations` holds the exported extras (`base_fan`),
  `test_configurations` the never-exported ones (`bare`); `params.exported_configurations(slug)` lists what is exported.
- `parameters/variants/<slug>.json` is generated by `python -m cad.layout write`; never edit it by hand. The case master's
  build set is derived from a hand-written overrides file by `python -m cad.layout derive` (see `layout.derive_document`).

## Commands (repository root, `.venv\Scripts\python` on Windows)

    python -m pytest cad/tests -q                          all tests (set MCC_REQUIRE_OPENSCAD=1 to make the live ones fail instead of skip)
    python -m cad.layout write | check                     write / verify the parameter sets
    python -m cad.layout derive SPEC --out OUT [--check]   derive a set from a base set plus overrides (the build set of the case master)
    python -m cad.tools.scad_export write | check | report re-derive cad/ data from lib/mcc, verify it, list rows for the manual pass
    python -m cad.tools.layout_oracle write | check        re-derive / verify cad/fixtures/scad_layout.json

## Until the cutover (issue #86)

`lib/mcc` is the frozen oracle and `cad/` its verified mirror: the data files are produced by `cad/tools/scad_export.py`
from OpenSCAD's own evaluation, and `cad/fixtures/*.json` hold what OpenSCAD evaluated. Do not edit the data files by
hand; a value changes in the oracle by a recorded decision and the tool re-derives it. `cad/tools/**`, the fixtures'
role as a gate and `tests/test_scad_sync.py` are deleted at the cutover; everything else stays.
